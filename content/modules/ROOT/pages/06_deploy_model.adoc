# Model deployment 

In this section we will deploy our model and serve it in our RHOAI instance. +
The good practices suggest everything as code, but as we are just getting to know Openshift AI, we will use RHOAI dashboard to get familiar with it.

Let's first take a look at RHOAI feature called *model catalog*. 

## Model Catalog

The model catalog provides a curated library where data scientist can discover and evaluate the available generative AI models to find the best fit for their use case. Models found here are from different providers and OpenShift AI administrators can configure available repository sources for models displayed in model catalog. Default model catalog provided by Openshift AI, includes models from providers such as Red Hat IBM, Meta, Nvidia, Mistra AI and Google. 

In RHOAI dashboard, under `AI hub` group, select `Catalog` to check the models available in your model catalog:
[.bordershadow]
image::06_model_catalog.png[]

[TIP]
====
You probably noticed that some of the models have a `validated` label.

Validated models are benchmarked for performance and quality using leading open source evaluation datasets.
====

Selecting a model from this catalog opens details overview with description, license, tensor type and more details. +
The `Performance insights` section offers key performance metrics when running selected model on a popular GPUs.

One important detail to know is how to consume the model 🤔 +

image::06_model_endpoints.png[]

In the background, OpenShift created few new resources, that you can check from terminal in your namespace using:
[.console-input]
[source,bash]
----
# inference pod
oc get namespace <userX-workshop> -oyaml | grep '<your-model-deploy-name>'

# Serving runtime resource
oc get servingruntimes
oc describe servingruntime <your-model-deploy-name>

# Inference service resource
oc get inferenceservice
oc describe inferenceservice <your-model-deploy-name>

# Route on which model is served via REST API
oc get route <your-model-deploy-name>
----

As previously mentioned, RHOAI brings several serving runtimes out of the box. It also supports the ability to add your own serving runtime, in which case, it would be up to the users or administrators to configure, adjust and maintain your custom runtimes.

The resources we just observed in OpenShift, can be stored as yaml files and used for GitOps deployments according to good practices ✨
