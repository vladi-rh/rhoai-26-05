# Introduction to Kubeflow Pipelines

In this module we will learn about how Kubeflow pipelines are defined and how they can be run in Openshift AI with some examples.

. Start the workbench, we created in one of the previous exercises. 
. When the workbench starts running, open it and clone the following repository: `https://github.com/redhat-ai-services/kubeflow-pipelines-examples.git`. +
Let's explore the content of repository we just cloned

+
[.bordershadow]
image::10_kfp_cloned_pipelines.png[]

. Rename the `example.env` file to `.env`

. Open the `.env` file. We need to change some of the values.
.. In the `DEFAULT_STORAGE_CLASS` add the default storage class in your cluster (in our case that's `gp3-csi`. You can check in OpenShift console).
.. The `KUBEFLOW_ENDPOINT` value is the `ds-pipeline-dspa` route in the `userX-workshop` namespace +
`echo "https://$(oc get routes ds-pipeline-dspa -ojson | jq -r .spec.host)"`
.. The `BEARER_TOKEN` which you can get using `oc whoami --show-token` 

+
The env file should look as follows after all the changes are done.
[source,python]
----
DEFAULT_STORAGE_CLASS="gp3-csi"
DEFAULT_ACCESSMODES="ReadWriteOnce"
KUBEFLOW_ENDPOINT="https://ds-pipeline-dspa-userX-workshop.apps.cluster-abc123.abc123.example.com"
BEARER_TOKEN="sha256~123ABC456def987abcXY-_def987abc321xyz~"       # oc whoami --show-token
----

. Confirm you are in the root of the cloned repository `kubeflow-pipelines-examples`.

. edit current `Pipfile` to update `python_version` to "3.12" (currently it's older version)

. Install pipenv with following command: `pip install pipenv`

. Now we can install all the packages that are defined in the Pipfile by running `pipenv install`

. Our environment is ready to run all the examples. Check if you get an output with the command: `pip list | grep kfp`

. Run the `09_secrets_cm_pipeline.py`. This pipeline shows how we can access secrets and config maps in out pipelines.
+
Hint: We need to add configmap and secret. 

+
.Solution
[%collapsible]
====

[.console-input]
[source,yaml]
----
---
apiVersion: v1
kind: Secret
metadata:
  name: my-secret
  namespace: userX-workshop     # adapt to your project name
type: Opaque
stringData:
  my-secret-data: thisisaVERYsecretvalue
---
apiVersion: v1
kind: ConfigMap
metadata:
  name: my-configmap
  namespace: userX-workshop     # adapt to your project name
data:
  my-configmap-data: thisisaconfigmapvalue
----

Save these as single yaml (pay attention to the `---` separator and run `oc apply -f my-file.yaml`

====

. Run the `10_mount_pvc_pipeline.py`. This pipeline shows how we can access PVCs in a pipeline.

+
Hint: We need to add PVC

+
.Solution
[%collapsible]
====

[.console-input]
[source,yaml]
----
kind: PersistentVolumeClaim
apiVersion: v1
metadata:
  name: my-data
  namespace: userX-workshop     # adapt to your project name
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 1Gi
  volumeMode: Filesystem
----
====
